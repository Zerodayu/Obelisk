# Phase 2A observed defects and limitations

These observations reproduce against unmodified Python application code with synthetic workbooks and mocked Gemini. See the latest [results](PRE_UAT_RESULTS.md) and each referenced test's evidence for timestamps, hashes, expected and actual output. No production fixes were made.

## D-001 — UT-004: invalid numerical workbook inputs accepted

Reproduce with the README interpreter command plus `--case UT-004`. The fixture has two synthetic students and two CLOs, direct scores normally 20/25 + 40/50 + 20/25 and rating 4.5/5. Each scenario independently mutates only temporary workbook cells:

| Mutation | Expected | Observed |
| --- | --- | --- |
| First period score -1 | Reject negative raw score | Accepted; direct fraction 0.59 |
| First period score 26 with maximum 25 | Validate/reject score exceeding period maximum | Accepted; direct fraction 0.86 |
| First period score `invalid-score` | Reject nonnumeric score | Converted to null; accepted with direct fraction 0.60 |
| Indirect rating `invalid-rating` | Reject nonnumeric rating | Converted to null; accepted with indirect null and direct-only fallback |

`ExcelExtractor._as_optional_float` silently converts unparseable text to null. `SimpleTransformer._transform_v2_records` does not check per-period negative/over-maximum scores. Composite helper range checks do not replace raw-score validation when the total fraction remains in range.

Above-maximum scores may involve an intentional extra-credit policy; stakeholders should confirm that policy before deciding the fix. Negative and nonnumeric inputs still require an explicit handling decision. The tests preserve the submitted validation expectation and record FAIL rather than changing application behavior.

## D-002 — UT-004: conflicting duplicate identity/CLO blocks accepted

Use the same isolated UT-004 command. Duplicate the first student ID into the second student's Direct and Indirect rows (leave the synthetic names distinct): four records are accepted with only two unique `(student_id, clo_code)` pairs. Duplicate the second Direct CLO block label as CLO1 while retaining distinct Indirect CLO1/CLO2: the request is accepted; duplicate direct keys are overwritten and indirect-only CLO records may be reintroduced without direct evidence.

Expected: reject or explicitly surface conflicting duplicates so they cannot masquerade as valid student-CLO data. Identity/CLO registry existence is EXTERNAL to Python; these tests concern structural collisions and record uniqueness only. UT-014 passes for the designated well-formed 30×5 fixture; it does not negate this malformed-input finding.

## D-003 — UT-008: AI response schema not enforced by service

Expected: reject/validate the response or return structured `status=error`. A requested JSON schema in a prompt does not enforce provider output. Exact failing scenarios and response strings are recorded in UT-008 evidence. No live provider or endpoint request is needed to reproduce.
