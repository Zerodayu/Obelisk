## Identified original startup hazard

The original performance file audit hook called `tempfile.gettempdir()` on every
open event, including reads. In a fresh subprocess `tempfile.tempdir` is unset.
Python 3.13 `tempfile._gettempdir()` acquires `_once_lock`; directory discovery
then calls `os.open()` to probe the candidate directory. That triggers the audit
hook again, whose nested `gettempdir()` waits on the same non-reentrant lock.
The integration runner initialized its temp directory before installing guards,
so it did not encounter this path.

The new child's startup-stage evidence records
`temp_directory_was_uninitialized: true`, and after preinitialization proceeds
through imports, Redis identity verification, Uvicorn and lifespan startup.
This supports the original deadlock diagnosis. The original run did not capture
a stack at its hang, so its historical runtime location cannot be proved from a
trace. No production application change was necessary.
